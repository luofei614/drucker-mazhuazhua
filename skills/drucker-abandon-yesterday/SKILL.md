# 抛弃昨天审查（含举证责任倒置与体重控制律）

## R — 原文 (Reading)

> 当管理者准备启动一项新活动时，他应该先问问自己："假如不是已经在做，
> 现在的市场、团队、战略下，我还会启动它吗？"如果答案不是毫无保留的"会"，
> 那就表明应该停止或大幅减少对它的投入，释放出稀缺资源（特别是人才）。
>
> — 德鲁克，第5章 要事优先

> 启动新活动是风险最高的活动……因此，要把最有能力的资源（特别是那些经验丰富的人）
> 用于新活动。但是，除非他们现在承担的旧任务已经减少，否则他们根本无法承担新任务。
>
> — 德鲁克，第5章 要事优先

## I — 方法论骨架 (Interpretation)

几乎所有效率方法论都在讲"怎么加"和"怎么排序"，德鲁克说第一法则是**抛弃**。
理由：①机会的代价往往就是旧活动的延续——
昨天做得很好的事占用今天最优秀的人，就让今天的机会挨饿；
②启动新活动是风险最高的活动，必须用最有能力的人，
但他们正在做旧事，因此必须先为他们减负；
③组织对"放弃"有系统性的偏见——昨天的成功有自豪感，今日的失败只有问责，
  没有人愿意主动放弃。

**举证责任倒置**是本 skill 的核心创新：不是"证明它没用才废止"，
而是"假设不是已经在做，**现在还会启动吗**"，答案为否就停止。
这个问法把"放弃"的认知障碍显著降低——你不是在"抛弃一份功绩"，
你是在"重新做一次启动决策"。

**体重控制律**：启动新之前先砍旧。新任务风险极高，要用最优秀的人，
且他们必须已腾出手来。新人加旧事（不让旧事放手）= 旧事照做、新事半成。
这个顺序不能反过来。

**自我投资神圣化警告**：最危险的不是彻底失败（会自己消亡，不难），
而是"成功但已失去成效"的旧事（会持续很久，最危险），
甚至是"对管理者自我的投资"（本该做成却没做成，于是神圣不可侵犯）。
保留理由里若出现"这是当年我们打下来的"，那就是自我投资神圣化的典型信号。

## A1 — 书中的应用 (Past Application)

### 案例 1：杜邦 vs "马鞭子工厂"
- **问题**：两种相反的处置姿态。
- **方法论的使用**：
  - 杜邦：在产品走下坡路之前就淘汰它，主动布局下一条产品线。
  - 马鞭子工厂：当年做马鞭子的工厂，明明知道汽车会取代马鞭，仍坚持做，
    直到完全失去市场。
- **结论**：杜邦是"抛弃昨天"的范本；马鞭子工厂是"错过抛弃"的反面教材。
- **结果**：杜邦历次成功转型；马鞭子工厂消失。

### 案例 2：十年日落条款
- **问题**：政府计划往往几十年不评估，积压大量无效效投入。
- **方法论的使用**：德鲁克提议所有政府计划设 10 年日落条款——
  除非明确证明继续有效，否则自动终止。
- **结论**：举证责任倒置的制度化版本——把"证明无效"反转为"证明有效"。
- **结果**：未实施，但其思路在多家企业与基金会的内部治理中被采纳。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 启动新业务/新产品/新项目之前。
2. 评估老产品/老业务的"是否继续"——尤其是"还在赚钱但已失去成效"的灰色地带。
3. 团队感情深不肯砍——需要结构性手段打破沉默。
4. 准备用"再投一批资源让老业务反弹"——这是典型的延迟放弃。
5. 做季度/年度规划、制定"明年重点"时。

### 语言信号（用户的话里出现这些就应激活）

- "要不要砍"
- "老业务还在赚钱舍不得"
- "启动新项目之前要做什么"
- "要不要停" / should we stop / sunset
- "产品下架" / kill a product
- "老产品不做了吧" / legacy business
- abandon / sunset / retire a product / how to end a project

### 与相邻 skill 的区分

- 与 `drucker-feed-opportunities` 的根本区别：
  - 本 skill 关心"如何**释放**资源"（砍旧）；
  - `drucker-feed-opportunities` 关心"如何**配置**资源"（投新机会）。
  - 顺序应先本 skill（释放）后 feed-opportunities（配置）。
- 与 `drucker-priority-posteriority` 的区别：本 skill 是**项目级**的砍/留决策；
  那个 skill 是**任务级**的优先/延迟排序。本 skill 决定"砍掉什么",
  那个 skill 决定"留下来做什么的顺序"。
- 与"成本控制/降本增效"：成本控制关心成本；本 skill 关心**资源配置方向**——
  砍的是机会成本，不是显性成本。
- 与"组织变革管理"：变革管理关心转型过程；本 skill 关心单次"砍/不砍"决策。

## E — 可执行步骤 (Execution)

### 第一步：列出所有"已经在做的事"

- 做法：列出过去 12 个月内组织仍在投入资源的项目/产品/计划——
  不分大小，按"占用人才的数量"排序。
- 完成标准：清单完整，包含每个项目的资源占用。
- 判停条件：清单不完整（用户遗漏老项目）→ 提示：遗漏本身就说明问题。

### 第二步：对每个项目问"举证问题"

- 做法：对每个项目问：
  **"假如不是已经在做，**现在的市场、团队、战略下，**我还会启动它吗？"**
  - 答案"会" → 保留。
  - 答案"不会"或"看情况" → 标记为"候选砍除"。
  - 答案"不知道" → 收集信息后回到本步。
- 完成标准：每个项目有明确的"会/不会/不知道"答案。
- 判停条件：用户用"它还在赚钱"作为保留理由 →
  提示：赚钱不代表有效；老业务可能在挤占未来机会——本 skill 的目标
  是机会成本最小，不是短期利润最大。

### 第三步：识别"自我投资神圣化"信号

- 做法：检查保留理由中是否出现以下信号：
  - "这是当年我们打下来的"——把团队过去的成就与项目绑绑定。
  - "不能让别人看笑话"——形象管理替代绩效判断。
  - "再给我们一点时间"——反复延迟。
  - "撤了对不起老员工"——把员工情感与项目命运绑绑定。
  - "换个负责人就好"——把人当项目问题的根因。
  这些信号出现即说明：保留理由不是绩效判断，而是情绪/政治判断。
- 完成标准：每个保留项目有"事实理由"和"非事实理由"分类。
- 判停条件：用户拒绝把"非事实理由"列为信号 →
  提示：本 skill 关心的不是理由本身，而是理由的来源——绩效判断 vs
  情绪/政治判断。

### 第四步：制定砍除与过渡

- 做法：对每个"候选砍除"项目：
  - **立即停止新投入**：不再启动新研发/营销/招聘。
  - **安排有序退出**：客户/团队/资源有序转移。
  - **明确终止条件**：写明何时彻底关闭。
  - **释放资源清单**：列出释放出的人才/资金/时间，并明确转投方向。
- 完成标准：每个砍除项目有明确的"终止条件 + 资源去向"。
- 判停条件：用户想"再说" → 提示：犹豫本身就是延迟放弃——
  本 skill 的核心是用结构性时间表替代犹豫。

### 第五步：上新之前先砍旧（体重控制律）

- 做法：任何新项目/新业务的启动，必须前置完成一项旧活动的减负——
  不是新加资源，而是**先释放资源**。
  - 若无法释放资源 → 不启动。
  - 若必须启动 → 明确哪个新项目延迟（或砍除哪个旧项目）。
- 完成标准：新项目立项书含"前置减负"条款。
- 判停条件：用户想在不动旧项目的情况下启动新项目 →
  提示：本 skill 的明确预测是：新旧并行 → 旧事照做、新事半成。
  必须先砍后立。

### 第六步：复盘与防再发

- 做法：12 个月后回顾本轮砍除：
  - 砍除后组织是否释放出预期资源？
  - 被释放的人才是否真的转向了机会？
  - 留下来的项目是否真的"还会启动"？
  - 是否有新的"不可砍除"项目出现？
- 完成标准：12 个月后有正式复盘记录。
- 判停条件：用户认为"砍了就完了" → 提示：复盘是下一次砍除决策的依据，
  不是事后总结。

## B — 边界与失败模式 (Boundary)

### 不适用场景 / 反例（违反任一即停用本 skill）

- **彻底失败的项目**：会自己消亡，不需要本 skill 的结构化砍除。
- **一次性活动**：会议、一次性活动、不可重复的事件——不在本 skill 范畴。
- **基础设施/平台型投入**：如基础设施、技术债、组织能力建设——
  这些不能用"今天还会启动吗"判断，因为它们是基础能力。
- **法律/合规义务**：不能用业务逻辑砍除。

### 失败模式（决策出错的早期信号）

- **以"赚钱"为由保留**：赚钱不等于有效；老业务可能在挤占未来机会。
- **以"团队感情"为由保留**：感情是合法的人性因素，但不是绩效判断。
- **以"换负责人就好"为由保留**：把项目问题的根因归为人，循环往复。
- **犹豫不决**：明知应砍但拖一年——时间越长代价越大（人员固化、客户依赖）。
- **新旧并行**：新旧同时投入 → 旧事照做、新事半成。
- **砍除时不安排资源去向**：砍掉项目但人才沉淀 → 浪费了诊断信号。
- **未做系统性盘点**：只砍眼前看到的 → 其他老业务继续挤占。

### 时代局限与作者盲点

- **1967 年的"项目"概念**偏短期工业项目；
  当代的"基础设施型产品/平台"不能简单套用本 skill——
  它们的"砍除"等于挖地基，需要重新设计判定方式。
- **马鞭子工厂的反例在数字时代是基础设施型业务**——
  当年做个人电脑的 IBM 错过了 PC 时代，是因为没在正确时机抛弃大型机业务，
  这是本 skill 的典型胜利案例；但反之若 IBM 抛弃过深，错过大型机市场
  也是失败——本 skill 的"举证问题"必须用当下市场判断，不能事后归因。
- **"对自我的投资"神圣化**：这一警告的发现依赖组织文化的开放度——
  在创始人驱动型/家族企业中，"自我投资"与"组织投资"难以区分，
  本 skill 的信号识别可能失效。

### 易混淆方法

- 与"产品退市管理"：产品退市关心"如何安全退出"；
  本 skill 关心"为什么要退出"。
- 与"业务转型管理"：业务转型关心转型全过程；本 skill 关心"砍/不砍"决策点。
- 与"组合管理（Portfolio Management）"：组合管理关心多项目的总配置；
  本 skill 关心单个项目的砍/不保留判断。

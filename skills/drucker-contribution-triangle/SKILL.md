# 贡献三问与贡献三维度（含"成果只在外部"）

## R — 原文 (Reading)

> 有效管理者专注于贡献。他从工作当中抬起头来，往外看向目标。他思考的问题是："我能做出哪些对我供职的这个机构的绩效和成果产生重大影响的贡献？"……所有的组织都需要在三个重要方面取得绩效：①取得直接成果；②确立并不断强化价值；③培育和开发将来需要的人才。
>
> — 德鲁克，第3章 我能做出什么贡献

## I — 方法论骨架 (Interpretation)

这个 skill 回答的是"我为什么在做这件事"。

它的地基是德鲁克的一条定义性断言：**组织内部无成果可言，成果全部存在于组织外部**。企业成果来自客户掏钱，医院成果体现在患者身上。由此推论——流程、会议、报表、协调，这些发生在内部的一切，在会计意义上都是**成本和努力，不是成果**。他甚至说"我们常说的利润中心，其实只是客气的称呼，企业内部实际上只有努力中心"。

在这个地基上，贡献的定义发生了两处关键位移：

1. **贡献不由你定义，由接收方定义**。你的产出只是一个"片段"——它本身不结果实，只有被另一个人当作输入才有效用。因此"可用性"的责任在生产者一侧：专家不能要求对方先学会自己的术语，必须用接收方的语言重述自己的成果。德鲁克称反向做法是"傲慢到近乎野蛮"。
2. **贡献必须覆盖三个维度，缺一都会走向衰落**：
   - **直接成果**：销售额、利润、患者护理——通常不言自明
   - **确立并强化价值**：组织"代表"什么——最容易被漏掉
   - **培育未来人才**：为明天准备的人——最容易被牺牲

三个维度的**相对权重随职位与情境变化，没有固定排序**。这是履新失败最常见的原因：职位变了，三个维度的权重也变了，而你还在沿用旧权重——德鲁克说这样"事也错误，方法也错误"。

一句话判据：**任何"我们内部做成了 X"的表述都不能算成果，除非能指认出外部哪一方因此改变了行为。**

## A1 — 书中的应用 (Past Application)

### 案例 1：银行代理部副总裁
- **问题**：他掌管一个"事务性"部门——处理代理业务的文书与流程，被视为成本中心，他自己也这么看。
- **方法论的使用**：他没有问"我怎么把这个部门做得更好"，而是问"我能做出什么贡献"，并去问了真正的使用者（银行的其他部门与客户）。
- **结论**：换个问题之后发现，这个部门握有大量客户财务信息，完全可以成为银行的营销触角。
- **结果**：一个事务部门变成了全行非常成功的营销队伍——**同样的工作，换了贡献的定义，产出完全不同**。

### 案例 2：布莱恩护士
- **问题**：某大医院里一位普通护士，工作"不是非常突出，连护士长也没有当过"。
- **方法论的使用**：她自己定下一条标准——每当做一件事，就问"这会让布莱恩护士满意吗？"这里"布莱恩护士"指的是**患者**。她把外部接收方内化成了一个可随时调用的判据。
- **结论**：贡献的判据必须是具体的人，而不是抽象指标。
- **结果**：她成了这家医院的标准制定者——不是因为她职位高，而是因为她始终从接收方一侧定义自己的工作。

### 案例 3：六十岁的连锁零售总经理
- **问题**：一位资深总经理，履历漂亮，习惯用自己最擅长的方式工作。
- **方法论的使用**：德鲁克指出——职位一变，贡献三个维度的相对重要性就变了。
- **结论**：他失败的地方不是能力，而是"还在用上一份工作的贡献权重"。
- **结果**：这被列为"管理者失败的最常见原因"之一。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 说不清自己这一季的工作对公司有什么用，只能用"我很忙""我做了很多"来描述。
2. 一份分析/报告/代码/设计交出去后没人用，专家抱怨"外行看不懂"。
3. 跨专业协作卡住（会计 vs 运营、算法 vs 临床、法务 vs 业务、数据 vs 业务线）。
4. **履新、转岗、晋升**——需要重新校准三个维度的权重。
5. 内部职能（数据平台、中台、法务、研发、HR）需要定义自己的价值，而没有外部付费客户。
6. 用"我们上线了多少""组织架构调整得多漂亮"来论证成绩时。

### 语言信号（用户的话里出现这些就应激活）

- "我做这个有什么意义" / 我的价值在哪 / 有什么用
- "没人用我做的东西" / 交出去了没人看 / nobody uses my work
- "外行根本看不懂" / 专业不对口 / 跨部门推不动
- "刚升职/刚转岗，该从哪入手" / 履新 / 新官上任
- "中台/平台/职能部门的 KPI 怎么定"
- "我掌管 XX 部门" —— 这是危险信号：从自己的权力或专业出发，而不是从贡献出发

### 与相邻 skill 的区分

- 与 `drucker-priority-posteriority` 的区别：**本 skill 判断"什么算成果"**（定性，向上向外看）；优先/延迟判断"这么多事中先做哪个"（定序，需要砍掉）。顺序是：先有贡献定义，才有排序依据。
- 与 `drucker-abandon-yesterday` 的区别：抛弃昨天是**减法**（砍掉不再有成效的旧事），本 skill 是**定义**（什么才叫有成效）。二者常连用：先用本 skill 定出贡献标准，再用抛弃昨天去砍。
- 与 `drucker-strength-staffing` 的区别：用人所长问的是"这个人可以做出什么贡献"（**对他人的判断**），本 skill 问的是"我能做出什么贡献"（**对自己的判断**）。但两者共用同一个贡献定义。

## E — 可执行步骤 (Execution)

1. **问出核心一问**
   - 原话：**"我能做出哪些对我供职的这个机构的绩效和成果产生重大影响的贡献？"**
   - 注意措辞：是"重大影响"，不是"任何贡献"；是"成果"，不是"努力"。
   - 完成标准：得到一个动词开头的、可验证的答案（如"让业务线能自助取数"），而不是名词（如"数据建设"）。
   - 判停条件：若答案是从自己的专业或权力出发的（"我掌管会计部""我是算法工程师"）→ **本步未完成，重问**。这是未走完的明确信号。

2. **在三个维度上分别作答**
   - **直接成果**：我这一季度交付了什么可被接收方确认的东西？
   - **确立并强化价值**：我让组织"代表"什么变得更清晰了吗？（**最常被漏掉**）
   - **培育未来人才**：我为明天准备了谁？（**最常被牺牲**）
   - 完成标准：三个维度各有具体答案，且不是把同一件事换个说法填三遍。
   - 判停条件：若某一维度长期为空，显式标注出来——这不是"没想好"，这是"组织正在这一维度上衰落"。

3. **指认接收方，直接问他**
   - 做法：找到产出的实际使用者，**尤其要包括非直属的、其他领域的人**，当面问：
     "你需要我对你做出什么贡献，才能让你对组织做出你的贡献？你什么时候要，以什么方式要，形式又是怎样的？"
   - 完成标准：能说出至少一位具体接收方的姓名，以及他要的时点、方式与格式。
   - 判停条件：若用户说"没有接收方，我是内部支持" → 继续追问，直到找到一个真实使用者。**不存在没有接收方的产出**；找不到说明产出本身就是无效的。

4. **检查是否把内部活动当成了成果**
   - 做法：把用户的成果清单逐条过筛，凡是"我们上线了多少 / 做了多少 / 流程多漂亮 / 架构多先进"，一律问一句：**外部哪一方因此改变了行为？**
   - 完成标准：清单里每一条都能指认出一个外部行为变化，或已被标记为"这是成本不是成果"。
   - 判停条件：无——这一步必须走完。

5. **履新/转岗时重估三维度权重**
   - 做法：明确写出新职位下三个维度的相对权重，并与旧职位对比。
   - 完成标准：能说出"在旧职位上我最看重第 X 维，在新职位上最该看重第 Y 维"。
   - 判停条件：若用户是履新 3 个月内，这一步是**必做**；否则可跳过。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **平台型 / 多边市场 / 开源社区**：谁是"外部"变得模糊——平台的"客户"同时是供给方，开源社区没有付费客户。整个贡献框架建立在"存在清晰外部"这个锚点上，锚点消失时本 skill 失效。
- **纯内部职能且"外部"是社会与监管**：法务、合规、财务——其成果由监管与社会定义，反馈周期以年计，短周期内无法用本 skill 验证。
- **目标本身高度争议的组织**：当被要求同时追求三个互不兼容的成果时，三维度框架只能诊断问题，不给解法。
- **成果周期极长的工作**：基础科研、基础教育的长期效果、艺术创作、长期基础软件工程——德鲁克自己在第 4 章承认"知识工作没有合适的检验手段"，此时三维度无法在操作前定义。
- **个人职业兴趣探索**：本 skill 问的是"组织需要我贡献什么"，不是"我想做什么"。

### 作者在书中警告的失败模式

- **把"埋头苦干"当贡献** —— 判据：成果清单里全是投入（工时、数量），没有接收方行为变化。
- **专家把沟通成本推给接收方** —— 判据：出现"他们应该先学会""这个太专业解释不清"。德鲁克称之为"把知识从学问变成卖弄玄虚的东西"。
- **职位变了但贡献维度不变** —— 判据：履新后仍在做上任时最擅长的事。

### 作者的盲点 / 时代局限

- **"组织内部无成果可言"是定义性断言，不是经验命题**：德鲁克直接把"成果"定义为外部交换的结果，于是"内部只有成本和努力"在定义上必然为真，**不可能被任何证据推翻**。这意味着本 skill 的整个地基是不可证伪的——它很有用，但你要知道它是公理不是定理。
- **"组织越小越接近完美"今天可能不成立**：与网络效应、平台效应、规模数据优势直接冲突。
- **组织边界今天已经模糊**：外包、众包、远程协作、跨组织项目网络，使"内部/外部"之分本身成为问题——而本 skill 的全部力量来自这个区分。
- **因果方向未证**：德鲁克假定"专注贡献 → 有效"，但也可能是反向——有效的管理者（已有资源与权力）才有余裕专注贡献。他所有的案例都是成功之后的回顾叙事。
- **样本偏差**：全书案例几乎清一色为 1960 年代男性、最高层、美欧大型机构。

### 容易混淆的邻近方法论

- **"客户第一"类口号**：本 skill 不是口号，它有可操作的判据（三维度 + 接收方提问模板 + 外部行为变化检验）。
- **KPI / OKR 制定**：它们把目标量化，本 skill 先判断"什么算目标"。先有贡献定义，再谈量化。
- **个人使命感 / 意义感探寻**：本 skill 从组织外部出发，不从个人内心出发。

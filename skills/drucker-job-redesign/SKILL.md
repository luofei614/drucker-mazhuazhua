# "无人胜任"职位诊断与重新设计

## R — 原文 (Reading)

> 任何一个职位，如果连续挫败了两三个人，而他们在之前的职位上都干得很出色，
> 那就必须认定这是一个常人无法胜任的职位，必须重新设计。……
> 经验告诉他设计并不合理，他不会试图去找个天才来担任此职，而是会重新设计。
> 他明白，组织面临的考验不在于找到天才，而是要有能力让平凡人做出不平凡的绩效。
>
> — 德鲁克，第4章 让长处富有成效

## I — 方法论骨架 (Interpretation)

大多数"招不到人"的真问题不是市场没有人才，而是**职位设计错了**。德鲁克给出的
判据非常硬：连续挫败两三个在上一岗表现出色的人，病因就在职位。

为什么？因为：①职位不是上帝造的，是容易犯错误的人设计的；②职位最初常常
为某个特殊人物量身定制，要求同时具备几种很难共存的性情（如"既擅长一线销售
推动，又擅长广告打动人"）；③行业普遍高失败率恰恰是"这个职位本身无人能胜任"
的同构证据。

处理路径明确：**归因翻转 → 诊断不可能性 → 拆分职位**。不是提高薪酬包、
不是加大招聘力度、不是"这次一定找到对的人"——这些动作在病因为职位时
都是徒劳，且会消耗优秀干部。

判别"前任是否真的出色"是关键证据：只有在"前任在原岗位确实卓越"的前提下，
归因翻转才成立。若前任本身不力，结论就是"招错了人"，本 skill 不适用。

## A1 — 书中的应用 (Past Application)

### 案例 1：五个"无人胜任"的职位
- **问题**：德鲁克在 ch04 明确举出五类高失败率职位：市场营销高管、美国大学校长、
  跨国公司国际业务副总裁、驻外大使、国防部长。
- **方法论的使用**：他诊断这些职位的共性是"要求任职者同时具备几种难以共存的
  性情或技能"。
- **结论**：处置不是找人，而是重新设计。例如把"国际业务副总裁"按市场共性
  拆成三个职位，每个职位要求一项明确的能力而非"全面"。
- **结果**：行业普遍认知"这些职位难做"，但传统做法是"再找更对的人"；
  德鲁克的方法是把"难做"翻译成"职位需要被拆开"。

### 案例 2：国际业务副总裁的拆分
- **问题**：某跨国公司为不同地理区域设统一的"国际业务副总裁"。
  多人失败。
- **方法论的使用**：识别各区域市场的共性（按业务类型而非地理拆分）。
- **结论**：把一个副总裁职位拆成三个（如按产品线 / 按市场成熟度），
  每个职位要求的具体能力明确。
- **结果**：失败率显著下降。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 某岗位两年换了三任，外招明星，行业普遍如此。
2. 用户准备加大招聘力度或提高薪酬以解决"招不到人"。
3. 用户描述某个职位时，出现"全面""成熟""能带兵也能打仗""既能 X 又能 Y"——
   这是职位本身可能需要拆分的语言信号。
4. 团队对某个职位长期抱怨，但没人质疑职位设计本身。
5. 用户描述"前任已离开，原因大家都知道是能力不行"——这种情况属"前任不力"，
   本 skill **不适用**，应回到 `drucker-strength-staffing`。

### 语言信号（用户的话里出现这些就应激活）

- "招不到合适的人" / can't hire for this role
- "这个岗位很难" / this role is tough
- "换了又换" / turnover / failed to scale
- "要全面一点的" / need a generalist / need a unicorn
- "整个行业都难招"
- "要不提高薪酬试试"
- "再找更对的人"

### 与相邻 skill 的区分

- 与 `drucker-strength-staffing` 的根本区别：**归因方向相反**。
  - `drucker-strength-staffing` 默认"病因在人"（候选人不行/标准不清），处处置换的是**选人判据**。
  - `drucker-job-redesign`（本 skill）默认"病因在职位"（职位本身无人能胜任），
    处处置换的是**职位本身**。
  - 判别切换条件：连续挫败 **2–3 个在上一岗表现出色**的人 → 切换到本 skill。
- 与 `drucker-indispensable-person` 的区别：那个 skill 看的是"已在岗的某人是否
  组织病灶"（诊断信号：少了就走不动），本 skill 看的是"职位本身是否无人能胜任"
  （诊断信号：换几个人都失败）。
- 与"招聘能力提升"：提高招聘官面试技巧、扩大候选人池、引入测评等都不解决
  本 skill 关心的问题——这是诊断错位。

## E — 可执行步骤 (Execution)

### 第一步：确认判据（关键开关）

- 做法：列出所有曾经在该岗位上失败的人。
  对每位，问：**他在上一岗表现出色吗？**
  - 若 ≥2/3 的人上一岗出色 → 病因大概率在职位，本 skill 启动。
  - 若大多数人上一岗也表现一般 → 病因在人，回到 `drucker-strength-staffing`。
- 完成标准：判据明确写出（"X/Y 失败者中，前任表现出色者有 N 位"）。
- 判停条件：用户无法列出失败者履历，或失败者中无人在上一岗表现出色 → 停止本 skill。

### 第二步：识别职位的"不可能性"

- 做法：写出该职位**同时要求**的能力/性情组合。
  例如"既要懂技术架构，又要能推动业务变革，还要能向上争取资源"。
  对每一对组合问：这两种能力在真实世界里是否**经常同一人**？
  - 是 → 不是"无人胜任"的原因。
  - 否 → 这对组合是"无人胜任"的根源之一。
- 完成标准：列出至少一对"难以共存"的能力/性情组合，作为拆分的依据。
- 判停条件：发现所有组合都常见 → 停止本 skill，回到 `drucker-strength-staffing`。

### 第三步：拆分职位（核心操作）

- 做法：把职位按以下任一原则拆开：
  - **按业务线/产品线拆分**：不同的业务需要不同的能力（如 ToB 与 ToC）。
  - **按市场成熟度拆分**：开拓期需要冒险者，守成期需要精细管理者。
  - **按时间相位拆分**：变革期需要变革型领导者，稳定期需要运营型。
  - **按地理拆分**：不同的区域市场要求不同的文化敏感性。
- 完成标准：拆出的每个新职位有**独立的关键成果**与**不重叠的能力要求**。
- 判停条件：拆出来的职位仍然"无人胜任" → 回到第二步进一步分析，或承认
  组织此阶段就不该进入这个业务。

### 第四步：过渡期处置

- 做法：拆分不可能当天完成，需要过渡方案。
  - **立即停止招聘**：避免新一轮挫败消耗优秀干部。
  - **临时"委员会"模式**：多人分工承担关键职责。
  - **明确终止条件**：写明新职位何时就位、何时开始废止旧职位。
- 完成标准：过渡期有人负责；明确过渡期不超过 X 个月。
- 判停条件：用户想"过渡归过渡，招聘还要继续" → 停止本步，
  明确告知：继续招就是在用组织的时间浪费最优秀候选人的职业生涯。

### 第五步：重新设计与评估

- 做法：新职位运行 6 个月后，回看是否仍存在"难以共存"的能力组合；
  若有，回到第三步继续拆。
- 完成标准：新职位各有一份"已验证可胜任"的人事档案。
- 判停条件：用户认为"招到人是问题，不是职位问题" → 停止本 step，
  明确告知：本 skill 的核心是归因翻转，组织要先承认"职位可能错了"，
  才能看到真相。

## B — 边界与失败模式 (Boundary)

### 不适用场景 / 反例（违反任一即停用本 skill）

- **新人 6 个月内表现不佳**：属正常磨合期，非"无人胜任"。
- **前任本身不力**：上一岗也表现一般的人 → 不在本 skill 范畴。
- **岗位本身的成功周期已过**：业务方向已不成立（如做胶卷的摄影胶片副总裁），
  不是职位设计问题，是业务问题，应回到 `drucker-abandon-yesterday`。
- **组织正处于剧烈变革**：6 个月内组织架构多次变动 → 因果归因困难，
  等待稳定期再判断。

### 失败模式（决策出错的早期信号）

- **加大招聘投入**：病因为职位时，加大招聘只能消耗更多优秀候选人，
  不能改变结论。
- **提高薪酬包**：薪酬再高也不可能让一个人具备两个不兼容的能力。
- **不断微调 JD 文字**：本质不变，只调措辞——属于自我安慰。
- **"行业普遍如此"作为不接受本 skill 的理由**：行业普遍高失败率恰恰是
  佐证而不是借口。
- **拆得过于琐碎**：把一个职位拆成 5 个，每个职位都不重要 →
  是另一种错误，会让协调成本超过收益。
- **拆分后无人在关键方向负总责**：拆分破坏了统一性，需要有"首席"角色
  在关键决策上行使否决权。

### 时代局限与作者盲点

- **德鲁克时代的"职位"概念偏静态**：2026 年的项目制团队、Squad、Pod
  不是传统"职位"，但同样的归因翻转仍有效——如果一个 Squad 角色连续挫败
  几任负责人，且每位负责人在原 Squad 都表现优秀，那是 Squad 角色设计错了。
- **创始人驱动型公司**：早期"创始人 = CEO = 产品经理"的多重角色
  在 5 人以下是合理的；本 skill 不适用于此阶段。
- **平台/网络效应行业**：用户基数是核心资源，"无人胜任"的高管职位的成因
  可能是"业务本身还在做增长实验"，此时拆分可能为时过早。

### 易混淆方法

- 与"组织架构咨询"：组织架构咨询关心**全公司**的结构；
  本 skill 只关心**单个无人胜任的职位**的重新设计。两者颗粒度不同。
- 与"高潜人才盘点"：人才盘点关心"人"的能力地图；
  本 skill 关心"职位"的能力要求。
- 与"招聘流程优化"：招聘流程优化改的是"怎么找人"；
  本 skill 改的是"这个职位对不对"。

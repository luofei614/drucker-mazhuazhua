0. 最快上手（30 秒）

你不需要记任何 skill 名字。 你只要用大白话说出你的处境，我会自动判断该用哪个方法，然后反问你要几个关键信息，最后给你一份能直接执行的结果。

你唯一要做的，就是别只丢一个词（比如只说"决策"），而是说清楚：谁 + 什么处境 + 卡在哪。

例子：❌「帮我想想用人」　✅「我想提拔一个业绩很好但跟同事处不来的人，拿不定主意」

下面第 1 章是 17 张"上手卡"，每张告诉你怎么说、我会问什么、我会怎么判断。对着抄就行。

1. 零门槛对话指南（核心）

1.0 三样信息，先准备好

不管用哪个方法，我都会追问这三样（有就一次说全，省得来回）：

我要的信息 说明 例子
你的处境 一句话：谁、什么场景、卡在哪 "我是产品负责人，团队开了个新业务线，但三个月没起色"
你试过的 已经做过什么、效果如何 "换了两任负责人，都待不住"
你想要的输出 要清单 / 要判断 / 要流程 "帮我判断是人的问题还是业务定位的问题"

1.1 L1 自我层（3 个）

drucker-time-log-consolidate · 时间实录与整块集中

你这样说：「我每天忙得要死，但一天下来感觉什么都没做成，时间不够用。」

我还会问你要：①你的岗位具体做什么（是不是随时要响应别人）②你时间大概花在哪几类事上（开会/沟通/写东西/救火）③你愿不愿意连续记 3–4 周实时时间日志。

我会怎么判断：先判断你的岗位有没有"可自由支配时间"——被算法实时调度、随时响应值班这类岗位，我会直接告诉你这套方法不适用，不让你白记三周。适用的话，我带你走四步：实时记录（不许靠记忆补）→ 三个诊断问题砍事 → 集中成 90 分钟整块 → 每月复盘防漂移。

drucker-org-time-waste-check · 组织时间浪费四类体检

你这样说：「我们公司会特别多 / 同一个危机反复发生 / 信息老是送错给错人。」

我还会问你要：①同一类危机今年出现过几次 ②你（或高层）处理人际摩擦、调解争议占多少时间 ③你开会占多少时间 ④有没有人收到过"格式不对"的信息。

我会怎么判断：用四个硬阈值体检——危机 ≥2 次、摩擦 >1/10、会议 ≥1/4、信息失灵，每个病症给结构性的修法（不是"少开点会"）。如果诊断结论是"这超出你的权限"，我会直说，不给你编一个个人层面能做的假动作。

drucker-contribution-triangle · 贡献三问与三维度

你这样说：「我做的这些事到底对公司有什么用？/ 刚升职，不知道从哪入手。」

我还会问你要：①你在什么岗位 ②你的产出最后是谁在用 ③你这一季具体交付了什么。

我会怎么判断：把你嘴里的"我做了 X"，翻译成"外部哪一方因为 X 改变了行为"——凡是"上线了多少、做了多少表"这种内部工作量，我会提醒你那是成本不是成果。然后在三个维度上逐个查：直接成果 / 强化价值（最常漏）/ 培育人才（最常牺牲）。

1.2 L2 用人层（5 个）

drucker-strength-staffing · 用人所长四法则

你这样说：「帮我写个 JD / 这个人该不该招 / 该不该提拔他。」

我还会问你要：①这个职位要交付什么成果 ②候选人在哪个重要领域有突出长处 ③这个长处跟这项任务相关吗。

我会怎么判断：用"用人三问"打分——重要领域有长处？与任务相关？能产生重大成果？三个"是"才用。并提醒你两条反常识：有高峰必有深谷（找完人=找平庸）；唯一的一票否决项是正直（不是能力、不是情商）。

drucker-job-redesign · "无人胜任"职位诊断与重设计

你这样说：「这岗位招不到人 / 两年换了三任都不行 / 整个行业都难招。」

我还会问你要：①前任在上一岗表现如何 ②这个职位同时要求哪几种能力 ③失败的人具体卡在哪一步。

我会怎么判断：关键看前任——连续挫败 2–3 个"在上一岗表现出色"的人，病因在职位不在人。我会帮你识别"要求几种难以共存的能力"（比如又要一线冲又要做品牌），然后拆成两个或更多职位。如果前任本身就不行，我会告诉你这是"招错人"，转去用人所长那条。

drucker-strength-appraisal · 长处型考评四问

你这样说：「绩效怎么写 / 业绩很好但难相处，怎么处理 / 要不要让他继续管人。」

我还会问你要：①对他的期望贡献是什么 ②对照目标的实际业绩 ③他在哪个方面已经做得很好。

我会怎么判断：先逼你列出"期望贡献 + 实绩"（没有参照系我不评估）。再用四问从长处起步，最后用一句话做唯一否决——"如果我有儿女，愿不愿意送到他手下去工作"（测的是正直）。

drucker-indispensable-person · "少不了的人"三诊断

你这样说：「他走了这边就转不动了 / 离不开他 / 他是我们最重要的资产。」

我还会问你要：①这个人具体卡在哪个环节 ②他走了最坏会发生什么 ③他是不是在替某个上级兜底。

我会怎么判断：把"少不了"从表扬翻转为组织病灶，只有三种解释且都是病——本人不胜任（要求太低才混得下去）/ 替无能上级兜底 / 掩盖一个迟早要爆的问题。三种都指向立即调离。我会帮你暴露那个被掩盖的问题。

drucker-managing-up · 管理上级：改方式不改内容

你这样说：「方案老被老板打回 / 老板听不懂 / 刚换了新老板不知道怎么配合。」

我还会问你要：①你老板最擅长什么 ②他过去做得最好的是什么 ③他喜欢看一页纸还是当面听。

我会怎么判断：帮你把目标从"让老板采纳我的方案"翻转成"让老板发挥长处"。改的是方式（呈现顺序、信息密度、书面还是口头），不是内容的对错。识别老板是"善读者"还是"善听者"，决定你交一页纸还是当面讲。

1.3 L3 聚焦层（3 个）

drucker-abandon-yesterday · 抛弃昨天

你这样说：「要不要砍这个老产品 / 老业务还在赚钱但越来越没劲，舍不得。」

我还会问你要：①这个业务如果今天是全新的，你还会启动它吗 ②它现在占用谁的时间 ③砍掉之后资源往哪放。

我会怎么判断：用举证责任倒置——不是"证明它没用才砍"，而是"今天还会不会启动它"，答案不是干脆的"会"就停。并提醒你"上新之前先砍旧"，砍掉释放的人立刻转投新机会。

drucker-priority-posteriority · 优先/延迟必须成对

你这样说：「这些事我该先做哪个 / 我列了优先级清单但还是忙不过来 / 年规划怎么做。」

我还会问你要：①你明确不做的有哪些 ②哪件是机会、哪件是止损 ③如果没压力，你会怎么排。

我会怎么判断：帮你把"优先任务"和"延迟任务"成对写出来——延后就是放弃，这才是难点。用四勇气法则排序（重将来不重过去 / 重机会不重问题 / 自选方向不随波逐流 / 目标高远不求安全），并提醒一次只推进一项、时间留余地。

drucker-feed-opportunities · 喂饱机会，饿死问题

你这样说：「该让谁去做这个 / 我们最能干的人在忙什么 / 增长和防守怎么摆。」

我还会问你要：①你现在最能干的那几个人在做什么 ②是在救火/处理历史遗留，还是在做增长。

我会怎么判断：判据只有一条——看最优秀的人在做什么。都在救火/维护过时产品线，组织就在"喂饱问题、饿死机会"。我会帮你把最优秀的人从问题转到机会上。

1.4 L4 决策层（6 个，按顺序）

drucker-decision-necessity · 决策必要性判断

你这样说：「要不要做这个项目 / 要不要跟进竞品的动作 / 他们一直说'再研究研究'。」

我还会问你要：①如果不做，情况会恶化吗 ②这个窗口会不会消失 ③它会不会自己变好。

我会怎么判断：三情境判定，只有"不决策会恶化"才必须立刻做；机会稍纵即逝才立刻动（且要大改不是小补）；会自愈就别管。帮你拦截"再研究研究"这种拖延——问"凭什么相信再研究会有新发现"。一旦决定做，绝不骑墙。

drucker-generic-vs-exception · 共性/例外四分类

你这样说：「这是个别问题还是要立规矩 / 我天天在重复处理同类事。」

我还会问你要：①这是第一次出现还是一直在发生 ②根本原因是什么 ③是特殊事件还是普遍事件。

我会怎么判断：先假设是共性问题（共性才能治本），四分类处置：真共性立规则 / 对我方是特例但本身共性→借规则 / 真例外个别处理 / 新共性第一次出现→按共性处理。反复决策同一类事 = 你没建原则。

drucker-boundary-conditions · 边界条件 + 先正确后妥协

你这样说：「这个决策的目标是什么 / 什么情况下我该放弃 / 大家分歧太大，怎么妥协。」

我还会问你要：①这件事最低必须达成什么 ②什么条件下你会认为它失败了、该放弃。

我会怎么判断：帮你定义"边界条件"（最低目标），这是研判不是计算。然后用"先正确后妥协"——先想清楚完整解，再谈可接受的妥协，用"半块面包 vs 半个婴儿"检验（妥协后连边界都不满足，就是半个婴儿）。

drucker-decision-to-action · 决策转化为行动

你这样说：「决策定了但没人执行 / 三个月了还停留在口号 / 怎么把战略拆成动作。」

我还会问你要：①这个决策要改变谁的行为 ②谁会因为不知道而继续按旧规则做 ③衡量和激励改了没有。

我会怎么判断：用四问分解——谁必须知情 / 采取什么行动 / 谁负责 / 行动长什么样才能施行。并强制检查"衡量/绩效/激励是否同步改"——没同步，决策会被悄悄废弃（不是有人反对，是没人按新规则做）。

drucker-dissent-first · 异见激发器

你这样说：「方案评审会一致通过了 / 总感觉哪里不对但没人反对。」

我还会问你要：①有没有人明确反对 ②反对者到底反对什么 ③反对者的立场在什么条件下能站得住。

我会怎么判断：无不同意见就不做决策——一致通过是"没人敢说"的信号，不是成熟信号。帮你主动制造异见（分派对立视角独立研究）、先假设反对者聪明且无恶意地理解他、把异见固化成"主方案失灵就启用"的备选方案。

drucker-opinion-and-measure · 观点检验与衡量标准替换

你这样说：「指标都在变好但一线抱怨越来越多 / 这个数据到底能不能信 / 要不要去现场看看。」

我还会问你要：①这些指标是谁定的标准 ②标准本身现在还适用吗 ③平均值会不会掩盖了集中分布。

我会怎么判断：决策从观点开始，不是从事实开始——先定"相关性标准"再收集事实。帮你质疑旧衡量标准（作新决策时旧标准通常已失效）、警惕平均值陷阱（事故集中在一两个岗位）、提醒"报告用处不大，走出去看现场"。

4. 决策流：我现在该用哪一类？

先 L1（自我）→ 再 L2（用人）→ 再 L3（聚焦）→ 最后 L4（决策），这是德鲁克原书的次序。

你的痛点是什么？
│
├─ 关于"自己" ────────────→ L1 自我层（时间 / 组织结构 / 价值定位）

5. 切换矩阵（避免误用）

5.1 归因方向相反（最易撞车）

看到的事实 默认归属 用这个
候选人都不行 / 团队一直换人 病因在人 strength-staffing（改选人判据）
连续挫败 2–3 个在上一岗表现出色的人 病因在职位 job-redesign（归因翻转）
他走了就停摆 / 离不开 病灶在人 indispensable-person（立即调离）

口诀：看外部候选人一直失败→职位问题；看已选错的人成为单点→人/组织问题；看候选人素质模糊→选人判据问题。

5.2 L3 顺序不能乱

abandon-yesterday（砍旧释放资源）→ feed-opportunities（资源放对位置）→ priority-posteriority（剩下的事排序）。

5.3 决策层流程顺序不能乱

decision-necessity → generic-vs-exception → boundary-conditions → decision-to-action →（过程中）dissent-first →（决策前后）opinion-and-measure。其中 opinion-and-measure 横切其余五步。

7. 已知陷阱与边界

7.1 五条最易踩的反常识

  1. "用人所长"≠"容忍一切短处"——是把短处置于职位安排之外 + 正直一票否决。
  2. "决策要基于事实"在德鲁克这里是错的——应先定相关性标准，再收集事实。
  3. "管理上级"改的是方式不是内容——想教育老板必失败。
  4. "放弃老业务"的判据不是"它不行了"，而是"今天还会启动它吗"。
  5. "离不开的人"是组织病灶，不是对个人的表扬——应立即调离，不是加薪挽留。

7.2 五条时代局限（写在各 skill 的 B 段）

  • 样本偏差：原案例几乎清一色 1960 年代男性最高层；承担主要照护责任的人用"在家工作 90 分钟不接电话"类建议时前提已松动。
  • 数字泰勒主义：岗位本身被细颗粒度实时监控时（骑手/审核/客服），"集中整块时间"物理上不成立。
  • 组织越小越接近完美，今天可能不成立：网络/平台/规模效应让小组织未必更优。
  • 异步组织里的会议：会议 ≥1/4 默认是结构缺陷，但在异步优先的组织里可能是必要弥补——当作"值得追问"而非直接定罪。
  • "成果只在外部"在平台/开源/纯内部职能里失效：法务、合规的"外部"是社会与监管，反馈周期以年计。

7.3 结构性问题个人化的诚实

org-time-waste-check、job-redesign、indispensable-person 可能得出"超出你权限"的结论。我会如实说，不给你编假动作——这正是德鲁克被批评最多的一点（病根在结构，药方却全开给个人）。

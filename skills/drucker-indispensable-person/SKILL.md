# "少不了的人"三诊断与迅速调离

## R — 原文 (Reading)

> 对这种"少不了的人"只会有三种解释：这个人其实并不能干，只是因为对他的工作要求不高，
> 所以才混得下去；这个人的长处被用于支撑无能的上级；
> 这个人的长处被用于延迟某个严重问题的爆发，甚至用于掩盖这个严重问题的存在。
> 无论哪种情况，这个"少不了的人"都必须调走，而且行动要迅速。
>
> — 德鲁克，第4章 让长处富有成效

## I — 方法论骨架 (Interpretation)

"他走了我就转不动了"是一句必须被当作**诊断信号**而非事实陈述的话。
常识把它当成对一个人的最高褒奖——"你是不可或缺的"。
德鲁克把它整个翻转为**组织病灶的指示器**——越是"少不了"，说明越有问题需要被看见。

诊断只有三条可能的解释，且三条都是病：
- **本人其实不胜任**——只是因为工作要求不高才混得下去；
- **在替无能上级兜底**——他的长处在支撑一个本不该存在的工作流；
- **在掩盖一个迟早要爆的问题**——他的存在让组织可以继续回避某个根本性问题。

三条诊断都指向同一处置：**立刻调离**。这个"立刻"是德鲁克特别强调的——
犹豫会让调离变得代价更大，因为被掩盖的问题会持续恶化。

诊断的价值在于把"调离"从"个人去留"升级为"组织修复"。真正该追问的不是
"怎么留他"，而是"为什么组织允许单点依赖存在这么久"。
后续在 ch05、ch08 反复重申，是"喂饱机会饿死问题"原则在人事层面的应用。

## A1 — 书中的应用 (Past Application)

### 案例 1：马歇尔将军的"立刻调走"原则
- **问题**：二战期间美国陆军有许多"少不了的人"，散布在各战区。
- **方法论的使用**：马歇尔任陆军参谋长期间，听到任何人被评价为"少不了"，
  就立刻把他调走。
- **结论**：所有"少不了"的实质诊断都属三种解释之一。
- **结果**：用调离暴露了被掩盖的问题、组织问题，并让优秀干部获得更大平台。

### 案例 2：德雷斯塔特与卡普尔（ch04）
- **问题**：印度某大公司（一家钢厂）的两位元老长期占据关键岗位。
- **方法论的使用**：德鲁克将其作为"两个庸人顶不上一个能人"的反例——
  不只是单点依赖问题，还是**质量**问题。
- **结论**：长期"两缺一不可"会让组织丧失对真正长处的识别。
- **结果**：组织应当主动打破这种平衡，而不是维持。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 听到或说出"他走了这边就转不动了/他可不能走"时。
2. 做继任规划、组织盘点、年度人员盘点时。
3. 审批调岗/借调申请，被"少不了"挡回来时。
4. 某个人成为单点瓶颈，且被当作功绩表扬（不是问题）。
5. 评估薪酬调整以挽留某人——除非先完成本诊断，否则薪酬只是拖延问题。

### 语言信号（用户的话里出现这些就应激活）

- "离不开他" / indispensable / can't afford to lose
- "他走了就停摆"
- "单点瓶颈" / single point of failure
- "他是这边最重要的资产"
- "没有他我搞不定"
- "怎么留住他"

### 与相邻 skill 的区分

- 与 `drucker-strength-staffing` 的区别：那个 skill 关心**怎么选对人**；
  本 skill 关心**已选错/已陷入单点依赖如何处置**。
- 与 `drucker-job-redesign` 的根本区别：
  - `drucker-job-redesign` 看的是"**职位**本身是否无人能胜任"（连续挫败外部候选人）；
  - 本 skill 看的是"**人**是否在掩盖组织问题"（这个人本身在岗，但他的存在本身是病灶）。
  - 切换判据：候选者失败 → 那个 skill；候选人本人成为病灶 → 本 skill。
- 与"继任规划"：继任规划关心"将来谁接"；本 skill 关心"现在是否在掩盖问题"。
  顺序应先本 skill 后继任规划。
- 与"关键人才保留"：人才保留关心"如何让人满意从而留任"；本 skill 关心
  "他是否应该留任"。前者是假设留任为正，后者在质疑留任。

## E — 可执行步骤 (Execution)

### 第一步：识别"少不了"信号

- 做法：在评估某个人时，先搜索是否存在以下信号：
  - 同事/上级/下属说"他走了就停摆"。
  - 工作交接文档缺失或刻意不更新。
  - 此人缺席时（休假、病假）相关流程出问题。
  - 此人拒绝升迁/调动/借调。
  - 此人被反复描述为"特别重要"。
- 完成标准：识别出至少 1 条"少不了"信号。
- 判停条件：无任何"少不了"信号 → 停止本 skill，正常评估即可。

### 第二步：执行三诊断

- 做法：对每位被识别为"少不了"的人，逐一排查三种可能：

  - **诊断 A：本人其实不胜任？**
    - 检查：把此人的真实工作要求写出来。若长期不写要求 → "要求低所以混得下去"。
    - 询问：如果提升对他的工作要求，他还能产出当前成果吗？

  - **诊断 B：在替无能上级/流程兜底？**
    - 检查：他的上级是否被反复描述为"还行""一般""待观察"。
    - 询问：去掉此人，他的上级能撑多久？3 个月？3 周？

  - **诊断 C：在掩盖迟早要爆的问题？**
    - 检查：是否有人在他请假期间发现"原来 X 系统有这么大问题"。
    - 询问：若他离开 6 个月，谁会先抱怨？抱怨什么？

- 完成标准：每条诊断给出"是 / 否 / 不确定"。
- 判停条件：三项都是"否" → 重新评估；若三项都是"不确定" → 收集更多
  信息后回到本步。

### 第三步：选择处置路径

- 做法：诊断结论决定处置：
  - 任何一条"是" → **立刻调离**。
  - 三条都是"不确定" → 在 3 个月内构造一次"被迫缺席"（长休假、借调），
    让被掩盖的问题自己显现。
  - 三条都是"否" → 重新评估"少不了"信号本身，可能是评价偏差。
- 完成标准：处置路径明确，且有时间表。
- 判停条件：用户想"再观察一段时间" → 停止本步，
  明确告知：犹豫会让被掩盖的问题持续恶化，时间越长代价越大。

### 第四步：调离与问题暴露

- 做法：调离本身是诊断的执行，不是诊断的完成。
  - 调离后 3 个月内，密切跟踪"被掩盖的问题"是否显现。
  - 出现显性问题 → 启动对应处置（流程修复/系统重写/架构调整）。
  - 未显现 → 复盘调离决策本身，可能误诊。
- 完成标准：调离后 3 个月内有一次正式复盘。
- 判停条件：用户调离后认为"工作立刻恢复正常" → 停止本步，明确告知：
  这恰恰说明他确实在掩盖问题；应继续观察更长周期（6-12 个月）。

### 第五步：防再发——识别"单点依赖"并破除

- 做法：从此事件提炼组织级教训：
  - 单点依赖是怎么形成的（角色定义不清？流程设计错？）
  - 为何长期未被发现（考评机制？决策者机制？）
  - 制定防再发机制（强制休假、强制交接、关键角色双人轮值等）。
- 完成标准：组织级教训写明，且至少有一项防再发动作已上线。
- 判停条件：用户认为"这种小概率事件不需要系统化" →
  停止本步，明确告知：单点依赖不是偶发而是常态，必须系统化应对。

## B — 边界与失败模式 (Boundary)

### 不适用场景 / 反例（违反任一即停用本 skill）

- **新人辅导期（< 6 个月）**：新人被高度依赖属正常，不算"单点"——但应警惕
  6 个月后仍未打破依赖。
- **正在攻关的特殊角色**（如首席研究员、首席工程师），其"少不了"是因为
  问题特殊 + 任期有限 → 不属本 skill 范畴。
- **被架构性外部因素限制**：如某些关键岗位需要特定资质/许可，
  找不到替代人是事实限制，不是组织病灶。
- **决策者本人的真实可替代性极低**：CEO 的可替代性本就低，是事实而非病灶。

### 失败模式（决策出错的早期信号）

- **把"少不了"当褒奖**：在评优/嘉奖材料中写"不可或缺"——
  这是没看到本 skill 的诊断价值。
- **薪酬挽留代替诊断**：在没完成三诊断前就加薪挽留——
  只是拖延问题暴露。
- **犹豫不决**：知道要调离但拖一年 → 时间越长代价越大。
- **调离后未跟踪问题暴露**：调离本身不是处置，是诊断的执行；不跟踪就
  浪费了诊断信号。
- **未反思组织机制**：把责任全推给个人 → 下次还会发生。

### 时代局限与作者盲点

- **1967 年的"组织"概念偏向层级制**：当代的"网络化团队""远程协作""扁平组织"
  中的单点依赖更隐蔽（可能在某个 Slack 频道、某个隐性权威身上），
  本 skill 的诊断信号同样适用，但要扩展观察面。
- **马歇尔的"立刻调离"在创始人驱动型公司难以执行**——创始人往往就是
  "少不了的人"，且这种依赖是事实而非病灶。本 skill 不适用。
- **关键人才市场短缺**：某些领域（如顶尖 AI 研究员）确实"找不到替代人"，
  此时本 skill 建议的"立刻调离"会变成"赶走关键人才"——
  应承认市场限制，而非强行本 skill。

### 易混淆方法

- 与"知识管理 / 文档化"：文档化能减少"知识在脑袋里"的依赖，但不解决
  "工作流本身是错的"或"上级无能"的依赖。
- 与"教练/辅导"：教练能改善表现，但不解决"在掩盖问题"的本质——
  这是组织问题，不是个人能力问题。
- 与"组织架构咨询"：组织架构咨询关心全局；本 skill 关心具体某个人与
  病灶的对应关系。

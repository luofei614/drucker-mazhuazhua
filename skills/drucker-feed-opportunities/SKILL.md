# 喂饱机会，饿死问题

## R — 原文 (Reading)

> 在组织内关乎有效性的每一个领域，都应该喂饱机会，饿死问题
> （feed the opportunities and starve the problems）。
>
> 有效管理者会把人（包括自己在内）视为机会。
> 他知道，只有长处才能创造成果，而短处只会制造麻烦——
> 短处全无，则会成果全无。
>
> — 德鲁克，第4章 让长处富有成效

## I — 方法论骨架 (Interpretation)

"先解决问题"是常识的优先级——问题有痛感、有问责、有截止日期；
机会只有可能性。德鲁克说这是**被痛感牵着走**——
解决问题最多只能恢复昨日的平衡，机会才产出成果。

判据非常硬：**看最优秀的那批人在做什么**。
若他们都在救火、处理历史遗留、维护过时的产品线，组织就在"喂饱问题、饿死机会"。

更反直觉的是后半句——"短处全无，则会成果全无"。
一个全是优点、没有明显短处的人，意味着他也没有突出的长处，因此也结不出果实。
"修复短处"是**修补**，"放大长处"才是**创造**。

这条原则是 `drucker-abandon-yesterday` 的"资源去向"——
砍掉旧活动释放出的人才，必须立刻转投新机会，否则砍掉毫无价值。
也是 `drucker-strength-staffing` 的资源后盾——优秀的人放在机会上
比放在巩固防御位更有价值。

## A1 — 书中的应用 (Past Application)

### 案例 1：德鲁克给所有"五步法"的资源视角
- **问题**：有效性五步法（记录时间/贡献/长处/要事/决策）需要资源支撑。
- **方法论的使用**：德鲁克明确指出，每个领域都应"喂饱机会，饿死问题"。
- **结论**：这条原则贯穿全书，是管理者配置资源的元规则。

### 案例 2：ch08 结语的资源重申
- **问题**：在结语部分强调组织层面的资源观。
- **方法论的使用**：再次把"喂饱机会，饿死问题"作为组织层面的要求重申。
- **结论**：个人层面是判断（看最优秀的人在做什么），
  组织层面是制度（让机会有资源，让问题得不到资源）。

## E — 可执行步骤 (Execution)

### 第一步：列出最优秀的人当前在做什么

- 做法：识别组织内"最优秀的那批人"——按"在前岗位上做出过突出贡献"
  而非按职级。列出他们当前的工作任务分配。
- 完成标准：清单完整——不只是高管，也包括关键岗位的关键人。
- 判停条件：用户只列高管 → 提示：执行层的"最优秀"才是本 skill 关心的对象。

### 第二步：识别每项任务是"机会"还是"问题"

- 做法：对每项任务分类：
  - **机会**：创造未来成果的（新业务、新产品、新市场）。
  - **问题**：恢复昨日平衡的（救火、历史遗留、客户挽留）。
  边界判定：完成后能产生增量成果吗？不能 → 大概率是问题。
- 完成标准：每项任务有清晰分类。
- 判停条件：用户把所有任务都标"机会" → 提示：把所有任务都标机会
  说明分类失效——可能用户混淆"重要"与"机会"。

### 第三步：检查"最优秀的人"是否配置在问题上

- 做法：把第二步结果与第一步对照——
  若最优秀的人中有一半以上在处理问题，组织就在"喂饱问题、饿死机会"。
- 完成标准：明确写出"最优秀的人中 X/Y 人在处理问题"。
- 判停条件：用户认为"他们在处理最重要的事" → 提示：
  "重要"和"机会"不是同义词——重要的问题不等于机会。
  本 skill 的判据是机会，不是重要。

### 第四步：重新配置

- 做法：把最优秀的人从"问题"任务调到"机会"任务——
  - 直接调岗（高级岗位）。
  - 在保留岗位的同时调整任务分配（中级岗位）。
  - 让次优秀的人接手"问题"任务（配合培训或工具支持）。
- 完成标准：每位最优秀的人有明确的"机会任务"清单。
- 判停条件：用户想"等老问题处理完再调" → 提示：问题永远不会处理完——
  这是本 skill 的关键反直觉。

### 第五步：保护新配置

- 做法：让"最优秀的人不再被问题吞噬"成为制度性安排：
  - 设置"问题任务"的最长处置时间。
  - 设置"机会任务"的最低资源占比。
  - 在考核中明确"机会任务的产出权重"。
- 完成标准：有制度性保护机制。
- 判停条件：用户认为"这是临时安排" → 提示：临时安排不会改变系统——
  必须制度化。

### 第六步：观察与迭代

- 做法：3-6 个月后观察：
  - 最优秀的人在做什么？仍在机会任务上吗？
  - 组织新成果是否在产生？
  - "问题任务"是否在减少（问题被解决了，不再是负担）？
- 完成标准：3-6 个月后有可量化的改善证据。
- 判停条件：用户认为"短期内看不出" → 提示：本 skill 的回报周期
  通常是 6-12 个月，但"短期内的判断错误"代价更高。

## B — 边界与失败模式 (Boundary)

### 不适用场景 / 反例（违反任一即停用本 skill）

- **短期危机**：突发公共安全/法律/财务危机——不能"饿死问题"。
- **生命攸关场景**：医疗急救、消防、应急响应——必须先解决问题。
- **新员工培训期**：新人先在"问题"任务中学习是合理的，**仅限前 6 个月**。
- **组织核心能力的维护**：如基础设施运维、合规底线——这些不能用
  "喂饱机会饿死问题"判断，因为是基础能力。

### 失败模式（决策出错的早期信号）

- **以"重要"代替"机会"**：把重要的问题当作机会——
  重要的问题不等于机会，问题只是恢复昨日的平衡。
- **让最优秀的人救火**：救火最显眼的功劳，但代价是组织失去机会。
- **以"等老问题处理完"为借口**：问题永远处理不完——
  这是延后资源配置的典型借口。
- **"短期危机当常态"**：第一次危机是机会（解决它），第二次是系统问题。
- **无制度性保护**：临时调岗无制度——压力一来就回滚。
- **混淆"防守"与"问题"**：基础性防守（如安全合规）不是"问题"——
  本 skill 不适用于基础性防守。

### 时代局限与作者盲点

- **1967 年的"机会"**：德鲁克写作时"机会"主要是新市场/新产品；
  当代"机会"还包括技术变革（如 AI）、商业模式创新、组织模式创新。
  本 skill 的判据仍然适用，但"机会"的视野需扩展。
- **"最优秀的人"在创业期就是创始人/早期团队**——
  本 skill 在创业期不一定适用（创业期所有人都得救火）。
- **机会型业务与问题型业务并存**：B2B 服务性业务（如客服、运维）天然是
  "问题型"——本 skill 不应让客服人员全部撤去做"机会"任务，
  否则客服塌方。本 skill 的应用范围应限于"非基础性、非生命攸关"的领域。

### 易混淆方法

- 与"风险管理"：风险管理关心"降低不确定性"；本 skill 关心"把资源放在产出上"。
- 与"敏捷/Sprint"：Sprint 关心迭代；本 skill 关心资源配置方向。
- 与"战略规划"：战略规划关心长期方向；本 skill 关心日常资源配置。

# 共性/例外四分类与归类错误自检

## R — 原文 (Reading)

> 在面对反复出现的问题时，有效决策者的第一反应是：要从根本上解决问题，
> 而不是纠结于表面症状。……在决策过程中，决策者要问自己的第一个问题是：
> "这是个特殊事件，还是个一再出现的普遍事件？"如果答案令人不快，
> 就重新审视这个问题。
>
> — 德鲁克，第6章 决策的要素

> 需要频繁做决策的管理者，其实既懒惰，又无效。
>
> — 德鲁克，第6章 决策的要素

> 错误地对待例外和特例，把它们当成共性问题的症状；以及另一种错误——
> 把新事件当成旧问题。
>
> — 德鲁克，第7章 有效的决策

## I — 方法论骨架 (Interpretation)

每个具体决策都该被问"这是共性问题还是例外？"。德鲁克给的默认先验非常硬：
**先假设问题具共性**——理由是共性问题才能被"治本"，例外只能被"安抚"。
问题归类对了，决策立竿见影；归类错了，决策越多越糟。

四分类：
①**真共性**（同一根因）→ 立规则，规则化处置。
②**对我方是特例，但本身是共性的问题** → 借鉴他人经验，立通用规则。
③**真例外** → 个别处理，不试图建立规则。
④**新共性问题的第一次表现**（最易误判）→ 按共性处理。

最有洞察力的判据："**如果你在同一类事情上不断做决策，说明你没建立原则——
律越繁杂，律师越无能**"。决策频率本身就是无效度的指标。

三种归类错误必须自检：
①把共性当一连串特例（实用主义，必然挫败徒劳）；
②把新事件当旧问题套旧规则（路径依赖）；
③对根本问题的定义似是而非或不完整——一知半解比完全错误**危害更大**，
因为错误的解释会被事实推翻，而貌似有理的不完整假设会被当成道德规范
（难以被自我更正）。

## A1 — 书中的应用 (Past Application)

### 案例 1：把"第一次表现"按共性处理
- **问题**：一个新现象第一次出现时，管理者倾向把它当"特例"处理。
- **方法论的使用**：德鲁克在 ch07 明确警告——新共性问题的第一次表现是最易误判的，
  应该按共性处理而非例外。
- **结论**：第一次出现就按共性处理 → 立规则；规则化让后续出现该问题时
  立即有标准。
- **结果**：避免"第一次特例处理、第二次特例处理……反复特例"。

### 案例 2：决策频率作为有效度指标
- **问题**：管理者疲于决策。
- **方法论的使用**：德鲁克指出"需要频繁做决策的管理者，既懒惰又无效"——
  没建立原则，所以每个具体问题都要重新决策。
- **结论**：决策频率是无效率的信号。
- **结果**：建立原则 → 决策变少 → 决策质量变高。

## E — 可执行步骤 (Execution)

### 第一步：列出近期反复处理的问题

- 做法：列出过去 6-12 个月内反复出现的问题（≥3 次）。
- 完成标准：清单完整。
- 判停条件：清单不完整 → 提示：用户可能在用"特例"标签隐藏共性问题。

### 第二步：对每个问题进行四分类

- 做法：把每个问题分到四类之一：
  - **真共性**（同一根因）→ 立规则。
  - **对我方是特例，但本身是共性的问题** → 借鉴他人经验。
  - **真例外** → 个别处理。
  - **新共性首演** → 按共性处理，立规则。
- 完成标准：每个问题有明确分类。
- 判停条件：用户把所有问题归为"特例" → 提示：默认先验是共性——
  大量"特例"说明归类失效，需重新审视。

### 第三步：识别归类错误的三个信号

- 做法：自检三种归类错误：
  - **错误 1**：把共性当一连串特例（用户答"具体问题具体分析"太多次）。
  - **错误 2**：把新事件当旧问题套旧规则（用户提出"按上次那样处理"）。
  - **错误 3**：根本问题定义不完整（用户的解释"看似合理但无法证伪"）。
  出现任一 → 重新归类。
- 完成标准：三种错误都被检查。
- 判停条件：用户拒绝自检 → 提示：本 skill 的核心反直觉是"归类错误
  比决策错误代价更大"——必须自检。

### 第四步：处理真共性（规则化）

- 做法：把真共性问题立规则：
  - 写出根因。
  - 写出处理规则（含触发条件 + 标准动作 + 边界）。
  - 试点验证。
  - 推广。
- 完成标准：每个真共性问题有规则文档。
- 判停条件：用户认为"规则化太死板" → 提示：规则化是降低决策频率的关键——
  没有规则就永远疲于决策。

### 第五步：处理真例外（个别化）

- 做法：对真例外问题：
  - 写明"为何是例外"（具体边界条件）。
  - 写明"如何个别处理"。
  - 跟踪结果——若再次出现 → 重新归类（可能变成新共性首演）。
- 完成标准：每个真例外有明确边界与处置。
- 判停条件：用户认为"例外不需要边界" → 提示：例外必须有边界——
  否则会蔓延为"我什么都是例外"。

### 第六步：建立决策频率监控

- 做法：建立机制监控自己的决策频率——
  若某类问题决策频率上升 → 重新评估规则化程度。
- 完成标准：决策频率有定期回顾。
- 判停条件：用户认为"决策频率不可监控" → 提示：记决策日志即可，
  是本 skill 的关键副产品。

## B — 边界与失败模式 (Boundary)

### 不适用场景 / 反例（违反任一即停用本 skill）

- **纯一次性事件**：确实只发生一次的问题——不属本 skill 范畴。
- **纯个体例外**：某人特有行为造成的问题——可能是 `drucker-strength-staffing` 范畴。
- **紧急危机**：救火期间不宜做归类分析——先把火灭了再说。

### 失败模式（决策出错的早期信号）

- **把所有问题归为"特例"**：默认先验是共性——大量特例说明归类失效。
- **以"具体情况具体分析"代替规则化**：实用主义导致挫败和徒劳。
- **反复逐个处理同类问题**：决策频率上升 = 没建立原则。
- **新共性问题被当特例处理**：错失立规则的最佳时机。
- **一知半解的解释被当共识**：这种解释最危险——难被推翻，会被当成道德规范。
- **无决策频率监控**：不知道自己决策频率在上升。

### 时代局限与作者盲点

- **1967 年的"决策"偏工业时代战略决策**：当代大量组织决策是产品/技术决策，
  共性识别更复杂（特别是技术领域的"假设性共性"——以为是共性，其实仍是特例）。
  本 skill 的"默认共性"仍适用，但需配合"假设性共性需验证"的现代意识。
- **"一知半解的危害大于完全错误"**：1967 年的组织中"完全错误"易被发现
  （事实会推翻）；当代信息过载下"一知半解"更难被推翻
  （部分事实支持、部分反对，认知更难统一）。本 skill 的这一警告
  在当代可能比 1967 年更严重。
- **"默认共性"的边际递减**：组织规模越大，例外越多——
  本 skill 的"默认共性"在大组织中需要更强的证据支持（不是默认假设），
  因为错的代价比小组织大。

### 易混淆方法

- 与"标准作业程序（SOP）"：SOP 是规则化；本 skill 是归类（含决策要不要规则化）。
- 与"案例库 / Best Practice"：案例库是历史经验；本 skill 是**当下决策的归类方法**。
- 与"分类学 / Taxonomy"：分类学关心一般分类；本 skill 关心"决策前的归类"。
